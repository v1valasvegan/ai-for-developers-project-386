# Окошко

## Обзор проекта

- `backend/` — Rust + Axum; `frontend/` — React + TypeScript + Vite + Mantine.
- `api/main.tsp` — источник API-контракта; `tests/` — HTTP smoke-тест через сгенерированный SDK.
- Бронирование реализовано; данные типов встреч, записей и успешных ключей попыток хранятся в SQLite.

## Команды установки, сборки и проверки

- `mise run install` — зависимости и Git-хуки.
- `mise run dev` / `mise run stop` — запуск / остановка серверов; `mise daemons status` — состояние.
- `mise run build` — сборка; `mise run test` — тесты; `mise run lint` — линтер фронтенда.
- `mise run check` — все проверки, включая Rust-линтер, форматирование и безопасность; обязаны пройти до завершения изменения. CI запускает ту же команду.
- `mise run generate` — перегенерация API; `mise run fix` — форматирование с последующей проверкой diff.
- `mise run docker:check` — сборка release-образа и реальные браузерные проверки двух PORT, конфликтов и сохранности тома; входит в `mise run check`, требует Docker.
- Для деплоя и подключения MCP читать раздел «Docker и публичный деплой» в `README.md`. Публичный smoke запускается отдельно с явным `BASE_URL`; он создаёт синтетические записи и не удаляет их.

## Правила

- Коммиты — Conventional Commits: `feat:`, `fix:`, `chore:`, `docs:` и другие стандартные типы; формат проверяется commitlint.
- Каждый коммит реализации должен ссылаться на соответствующий тикет GitHub Issues: номер указывается в теме, например `feat: запись на свободный слот (#18)`, или в теле коммита — `Refs #18`.
- `api/generated/`, `frontend/src/api/generated/`, `backend/generated/` генерируются: вручную не редактировать. Проверка повторяет генерацию и обнаруживает расхождения.
- Линт-правила не отключать ради прохождения проверок. Исключение — только узкое, с причиной и согласованием человека; исключения безопасности имеют дату пересмотра.
- `.github/workflows/hexlet-check.yml` управляется Хекслетом: не редактировать и не удалять.

## Контроль приёмки

- Перед реализацией составь короткий чеклист требований из задания, Issue и договорённостей. Снимай пункты только по явному согласованию с пользователем.
- Перед «готово» сверь каждый пункт с фактом: файлом, тестом или ручной проверкой. Всё неподтверждённое назови как оставшуюся работу, а не как выполненное.
- После push проверяй обязательный CI для отправленного SHA и целевой ветки; ожидающий запуск ещё не зелёный.
- В итоге различай: готово локально, отправлено, CI прошёл. Коммит и push — с разрешения пользователя.

## Agent skills

Настройки скиллов агента. Служебное название раздела сохранено для совместимости с настройщиком.

### Трекер задач

Задачи и спецификации — GitHub Issues. Перед чтением, созданием или изменением задач читать `docs/agents/issue-tracker.md`.

### Метки разбора задач

Разбор задач использует стандартные метки. Перед разбором задач или изменением меток читать `docs/agents/triage-labels.md`.

### Доменная документация

Единый доменный контекст: `CONTEXT.md` и `docs/adr/` в корне. Перед исследованием кода читать правила в `docs/agents/domain.md`.

## Язык документации

- Рукописная документация, инструкции и отчёты — на русском. Английский сохраняется для необходимых технических терминов, команд, путей и идентификаторов.
- Точные служебные строки, от которых зависит работа скиллов, сохраняются: например, `Agent skills`, `Wayfinding operations` и `PRs as a request surface: no.`. Окружающие пояснения — на русском.
