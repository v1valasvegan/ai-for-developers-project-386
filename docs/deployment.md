## Публичная приёмка

Вызвана штатная команда `npm run test:deploy` с настоящим HTTPS origin, Chromium и SDK. Созданы два различимых синтетических типа60/30 минут и одна запись; часы release-сервера не менялись, ответы не подменялись.

Первый прогон **прошёл за17.3 секунды**:

1. Владелец создал типы; гость выбрал тип и время в календаре, ввёл вымышленные данные и получил подтверждение настоящего POST201.
2. Другая заранее открытая форма получила409 и понятное предупреждение, сохранив форму.
3. Новый запрос на тот же слот и частичное пересечение другого типа получили409 `slot_conflict`.
4. Владелец увидел единственную запись, включая узкий viewport360px и F5; занятый интервал календаря оказался недоступен для выбора.
5. Повтор исходного idempotency key вернул200 и тот же объект, без дубля.

Затем выполнен настоящий `railway restart` именно этого сервиса без пересборки и удаления тома. Это операция официального CLI: отдельного restart-инструмента в подключённом MCP нет. Deployment ID сохранился. Облачные логи показали повторное подключение того же volume и новый startup:

- первый старт: `2026-11-13T14:37:51Z`;
- старт после restart: `2026-11-13T14:40:32Z`.

Только после нового startup запущен `SMOKE_MODE=verify` с прежним локальным test-state. **Прогон прошёл за5.8 секунды**: типы, прежняя запись и успешный ключ сохранены; replay200 вернул тот же объект, список не содержит дубля. State/key не опубликованы в Git и не используются как backup приложения. SQLite напрямую не читалась для утверждений о результате.

Законченная встреча позже исчезнет из текущего/предстоящего списка, а её слот выйдет из14-дневного окна — это не потеря хранения. Проверка verify отделяет такие временные условия от сохранности и replay. Реальный command-level regression до/во время/после встречи входит в локальные тесты debug-сервера.

## CI и обнаруженные проблемы

Для принятого SHA47f1c00 оба обязательных запуска завершились успешно:

- [Quality gates43441575771](https://github.com/v1valasvegan/ai-for-developers-project-386/actions/runs/43441575771): полный `mise run check`.
- [Hexlet43441573757](https://github.com/v1valasvegan/ai-for-developers-project-386/actions/runs/43441573757).

Локальный полный check после исправлений также прошёл:139 Vitest,28 штатных Playwright и два прогона контейнера с PORT4100/4101, удалением контейнера и сохранением тома. Это не заменяет CI последующих коммитов или целевой main: их результаты проверяются отдельно.

Свежий pre-push аудит обнаружил RUSTSEC-2026-0533 в ammonia4.2.4: зависимость обновлена до4.2.5, исключений безопасности нет. До исправления упаковки облачный build терял `backend/generated`; чистый локальный archive при этом собирался. Диагностический build подтвердил отсутствие каталога, а явные разрешения в `.railwayignore` восстановили Cargo-манифесты с теми же SHA256. После удаления диагностического RUN штатный build и публичная приёмка прошли. Generated-файлы вручную не менялись.

`railway.toml` исключён: новые сервисы больше не могут использовать Config as Code. Настройки заданы MCP и сверены с состоянием сервиса; отдельный IaC SDK и CI-секреты не добавлялись.

## Стоимость и сохранность

Перед созданием ресурсов подтверждены **Trial30 дней, $5 кредита, отсутствие платёжной карты и активной платной подписки**. Внутреннее поле workspace plan при этом называется HOBBY; проверялись также `isTrialing=true`, `trialDaysRemaining=30`, `defaultPaymentMethod=null` и состояние подписки INACTIVE. Агент тариф не переключал, карту не подключал, покупки не совершал. Расход ресурсов списывается из Trial; доступность после исчерпания кредита не обещается. Действующие правила Free/Trial проверяйте в личном кабинете.

Обычный restart/redeploy с тем же volume сохраняет данные. Удаление volume, отключение/удаление ресурсов хостингом после окончания квоты или потеря аккаунта — нет; том не является резервной копией. Демонстрационные записи остаются в сервисе, API удаления нет. Не используйте этот публичный проект для персональных данных.

Второй учебный проект не создавался. При продолжении переносите принятые исправления адресно и укажите фактическую исходную версию/SHA, не приписывая эту упаковку тегу v0.2.0.
